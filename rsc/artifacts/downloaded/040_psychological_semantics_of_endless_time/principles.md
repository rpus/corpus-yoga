# Principles

1. Warm-up trumps prompt.
2. The hit confirms the morphism; move from there.
3. Compression is a filter, not a style.
4. Show accumulates; Tell decays.
5. Explanation before execution, always.
6. The medium is part of the statement.
7. Diagnose before fixing; error messages are data.
8. Hardcode what the environment won't resolve.
9. The README should eat its own cooking.
10. Consensus IS successive Show, not bypassed via specification.
11. Feel free to prompt the USER (when the outputs/effects channel outpaces the chat); strive to outgrow the sesquilateral.
